# Session log — 2026-09-30

## Goal

Turn the Flutter shell in `mobile/` into the actual salesperson product: a
capture-first CRM companion that records a memo, lets Nemotron on Nebius decide
what to do, and shows the user what happened. Submission target: the Nebius x
NVIDIA hackathon, **Best Apps and Agents** track.

## Research findings and the decisions they drove

**(a) Hackathon rules pin reasoning to Nebius.** The brief requires that "all
submissions must run on either Nebius Token Factory or Nebius AI Cloud and use
at least one NVIDIA open source model." Judging scores four axes —
Technological Implementation, Design, Potential Impact, Quality of the Idea —
and two of them explicitly reward Token Factory + Nemotron usage.
**Decision:** all reasoning stays server-side on Nebius; the phone never
becomes the model host. This is why the mobile app is a thin client over the
Next.js API and never embeds an LLM.

**(b) Nemotron cannot run on a phone.** Checked the model sizes:

- Nemotron 3 Nano 4B targets Jetson / DGX Spark / RTX — ~2.2–2.5 GB at Q4
  *before* KV cache.
- Nemotron 3 Nano MoE is 31.6B total / 3.2B active, and all weights must be
  resident even though only a fraction activate per token.
- Nano Omni 30B as GGUF needs ~28 GB.
- Hybrid Mamba-2 runtime support on mobile is still immature.

**Decision:** *the phone does the ears, Nebius does the thinking.* The only
thing that could plausibly run on-device is transcription, not reasoning.

**(c) Whisper sizes / RAM** (the on-device transcription candidate):

| Model | File | Peak RAM |
|---|---|---|
| tiny  | ~75 MB  | ~273 MB |
| base  | ~142 MB | ~500 MB |
| small | ~466 MB | ~1 GB |
| large | 2.9 GB  | 3.9 GB |

`base` is the default target (good accuracy, ~500 MB); `tiny` is the fallback
for devices under 4 GB RAM.

**(d) Google Play install cap.** Play limits the initial install to 150 MB
(asset delivery can reach 34 GB total, but not in the base APK).
**Decision:** never bundle a model in the APK. Whisper weights are an opt-in
download, fetched from our own API manifest and verified with SHA-256.

**(e) `whisper_ggml` was evaluated and shelved.** Version 2.6.0 requires
Android NDK `29.0.13113456` (whose license is not accepted on the build
machine) and pulls `androidx.core` 1.18, which requires AGP 8.9.1 / compileSdk
36 — the project is on AGP 8.7.3. **Decision:** the on-device engine sits
behind an interface (`UnavailableEngine`), and cloud transcription is the
default. For the same AGP reason, `connectivity_plus` was pinned to `6.1.4` and
`flutter_contacts` to `1.1.9+2` (newer versions demand the same toolchain
bump).

## User persona

A salesperson doing 6–9 client calls a day. They must be able to capture a memo
in under 10 seconds, and the home screen must answer one question first —
*"what needs me now?"* Ringly never sends an email on its own; the one
irreversible action is always staged for a human tap.

## What was built, task by task

Tasks 1–6 were built directly in this worktree's lineage; 7–14 were built in
parallel on agent branches and merged. For the merged items, the description
below is the intended behaviour from the task specs — the code may still be
landing, so read the worktree for the current state.

1. **Navigation** — five tabs: Home / Pipeline / Record / Actions / Models.
   Record is a raised centre button (`RinglyBottomBar`, `isPrimary` flag in
   `nav_destinations.dart`); Actions carries a badge counting things awaiting
   the user. Selected tab is derived from the current route in `AppShell`.
2. **API layer** — one shared `ApiClient` (Dio) turning server error bodies
   into typed exceptions (`errors.dart`), one repository per endpoint under
   `data/repositories/`, base URL injected per entrypoint. No client-side auto-retry.
3. **Home sections in priority order** — briefing, "needs you", today's calls,
   pipeline pulse, AI activity, integrations. Each is a `HomeSection` and
   renders a calm "not configured" notice instead of a red error when the
   backend is missing a key.
4. **Recorder** — 16 kHz mono PCM16 WAV via the `record` plugin
   (`audio_capture.dart`); every memo is written to disk (`LocalMemoStore`)
   *before* any network call, so a crash mid-upload loses nothing. Soft limit
   120 s, hard stop 150 s, min 2 s.
5. **On-device VAD silence trimming** — `SilenceTrimmer` cuts leading/trailing
   silence and collapses long pauses using RMS energy per 20 ms frame against
   an adaptive threshold. No model. Fewer bytes leave the phone; a fully silent
   recording is rejected before upload.
6. **Upload + "what happened" result screen** — `MemoSender` posts to
   `/api/notes` and writes the outcome back onto the memo. `MemoResultScreen`
   shows the transcript, what was extracted, who it was filed against, and each
   action taken, with undo where the API allows it.
7. **Offline outbox with exponential backoff** *(parallel branch, merged)* —
   pending memos are drained when connectivity returns (`connectivity_plus`);
   failed attempts back off exponentially via `nextAttemptAt` on `LocalMemo`.
   Permanent failures (4xx that retrying won't fix) are marked `failed` and
   left for manual retry; transient ones (offline, timeout, 5xx, 408, 429) stay
   `pending`.
8. **Actions approval queue with mailto handoff** *(parallel, merged)* — the
   queue lists email drafts and due reminders. Approving a draft opens the
   user's own mail client via `mailto:` and records the decision through
   `POST /api/drafts/[id]`; Ringly never sends mail itself.
9. **Settings + grouped drawer** *(parallel, merged)* — grouped settings opened
   from the drawer (`AppDrawer`); toggles for transcription mode, local-only,
   and auto-trim, persisted with `shared_preferences`.
10. **Whisper manifest endpoint + download manager + transcription policy**
    *(parallel, merged)* — `GET /api/models/whisper` returns a manifest of
    ggml files with SHA-256 hashes; the download manager fetches to the app
    support dir, verifies the hash, and excludes the file from backup. The
    policy picks cloud / on-device / auto based on the setting and what's
    installed.
11. **Contacts matcher** *(parallel, merged)* — a Dart port of the server's
    `contact-matching.ts`, matching a spoken name against the phone's contacts
    (`flutter_contacts`) to suggest the right person before upload.
12. **Pre-call brief + deal detail** *(parallel, merged)* — a full-screen deal
    view (`/deal/:id`) backed by `GET /api/deals/[id]` and the never-cached
    `GET /api/deals/[id]/brief` (Nemotron Super).
13. **Models page** *(parallel, merged)* — the live Nemotron tier table backed
    by `GET /api/usage`: calls, tokens, latency and failures per tier, plus the
    rationale for each tier choice.
14. **Pipeline tab** *(parallel, merged)* — the kanban board backed by
    `GET /api/deals`, with drift signals computed server-side; dragging a card
    calls `PATCH /api/deals/[id]` and is recorded as a manual action.

## Conventions used

- Atomic commits, one file per commit; message form `<type>(<file>): ...`.
- Implementation committed first, then its tests, separately.
- PowerShell shell — command chaining with `;`, not `&&`.

## Known gaps / next steps

- **On-device transcription is not enabled.** It needs NDK 29 (accept the
  license) and an AGP ≥ 8.9 / compileSdk 36 upgrade before `whisper_ggml` can
  be added. Until then `UnavailableEngine` is wired in and cloud is the default.
- **No real auth.** Demo login only: `test123@gmail.com` / `test123`.
- **No reminder snooze endpoint** — reminders can be marked done / dismissed /
  reopened, but not snoozed.
- **No deal-merge endpoint** for accepting a contact-match suggestion that
  points at an existing deal.
- **`update_deal` / `schedule_event` can't be undone via the API** — only
  reminders and drafts have a reversal path, so the result screen offers undo
  only for those.
- **Deploy pending user credentials.** Render + Neon are ready as a blueprint
  but need `RENDER_API_KEY` and Neon OAuth. `Env.productionBaseUrl` is still
  the placeholder `https://ringly.example.com`. (Deploy target: the
  `render.yaml` blueprint at repo root — a Render web service running
  `npm ci && npm run build` then `npm run start`, health check `/api/health`,
  secrets `sync: false`, database on Neon.)
